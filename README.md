# piyushpraveen.com

Personal site of **Piyush Praveen**. Cyber security leader with 14 years in identity and privileged access. I lead teams, shape strategy and drive security transformation, and I share what I learn along the way.

Hosted on GitHub Pages at [piyushpraveen.com](https://piyushpraveen.com).

## What's here

| Path | What it is |

## What the site will cover

- **Basics:** plain-language guides to security fundamentals
- **Handwritten notes:** scanned notes and diagrams grouped by topic
- **Current topics:** short, dated takes on new vulnerabilities, regulation and trends
- **Breach analyses:** what happened, how access was abused, which controls failed and the takeaways
- **Blog:** longer pieces on identity, privileged access and security practice

## How to update the site

Everything below can be done from github.com in a browser. GitHub Pages redeploys automatically (usually within 1 to 2 minutes) every time you commit to `main`.

**Edit existing text**

1. Open `index.html` in this repo.
2. Click the pencil icon at the top right of the file view.
3. Make your change and click **Commit changes**.

**Add or replace a file such as an image or PDF**

1. Go to **Add file**, then **Upload files**.
2. Drag in your file. If the name matches an existing file it will replace it.
3. Add a short commit message and click **Commit changes**.

**Remove something**

1. Open the file and choose **Delete file** from the menu.
2. Commit the deletion.

**Add a new breach analysis**

1. Open `_templates/breach-template.txt` and copy its contents.
2. In the `_breaches` folder choose **Add file**, then **Create new file**.
3. Name it after the breach such as `capital-one-2019.md`.
4. Paste the template and fill in the title and date and tags and summary. Then write each section.
5. Click **Commit changes**. The analysis appears on the Breach analyses page within 1 to 2 minutes.

**Mark a section as live**

Each box in the "What you'll find here" section carries a "Coming soon" tag. When a section is ready, change the box to a link to its page and remove the tag.

**Check it went live**

Watch the green tick under **Deployments** on the repo's main page then refresh the site. If your browser shows the old version, hard refresh or add `?v=2` to the URL.
